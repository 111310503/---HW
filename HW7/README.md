# `diff`：兩個檔案差異比對（LCS 動態規劃 v.s. Myers 差分演算法）

`diff` 工具（如 Git 底層的程式碼比對）的核心目標是：**給定兩個字串（或兩個檔案的行集合）$A$ 與 $B$，找出將 $A$ 轉換為 $B$ 的「最短編輯腳本」（Shortest Edit Script, SES），即最少次數的「新增」與「刪除」操作。** 這與尋找兩者的「最長公共子序列」（Longest Common Subsequence, LCS）是完全對偶的數學問題。

---

## 方法一：動態規劃（LCS 標準解法）

### 1. 核心原理
動態規劃透過建立一個二維表格來窮舉所有子問題的最佳解。假設字串 $A$ 長度為 $M$，字串 $B$ 長度為 $N$。我們定義狀態 $DP[i][j]$ 為 **$A$ 的前 $i$ 個字元與 $B$ 的前 $j$ 個字元的最長公共子序列長度**。

狀態轉移方程式如下：

$$DP[i][j] = \begin{cases} 0 & \text{if } i = 0 \text{ or } j = 0 \\ DP[i-1][j-1] + 1 & \text{if } A[i-1] = B[j-1] \\ \max(DP[i-1][j], DP[i][j-1]) & \text{if } A[i-1] \neq B[j-1] \end{cases}$$

當表格填滿後，從右下角 $DP[M][N]$ 往左上角 $DP[0][0]$ 進行**回溯（Backtracking）**：
* 若 $A[i-1] = B[j-1]$，代表該字元保留（不變）。
* 若往上方 $DP[i-1][j]$ 移動，代表從 $A$ 中**刪除**了 $A[i-1]$。
* 若往左方 $DP[i][j-1]$ 移動，代表在 $B$ 中**新增**了 $B[j-1]$。

### 2. 複雜度分析
* **時間複雜度：** $O(M \times N)$。無論兩個檔案有多相似（甚至完全相同），都必須老實地把整張二維表格填滿。
* **空間複雜度：** $O(M \times N)$。為了回溯路徑，必須保留整張表格（若採用 Hirschberg 演算法結合分治法，可將空間壓縮至 $O(\min(M, N))$，但實作複雜且常數時間開銷變大）。

## 方法二：非動態規劃（Myers 差分演算法 — 圖論貪婪搜尋）

Eugene Myers 在 1986 年發表的論文《An O(ND) Difference Algorithm and Its Variations》是現代 GNU `diff` 與 `git diff` 的預設核心演算法。它捨棄了填表的動態規劃思維，將問題轉化為**圖論中的最短路徑搜尋**。

### 1. 核心原理
將比對過程視為在一個 $(M+1) \times (N+1)$ 的網格（Edit Graph）上從 $(0,0)$ 走到 $(M,N)$：
* **向右走一步** $(x, y) \to (x+1, y)$：代表**刪除** $A[x]$，編輯距離 $D$ 加 1。
* **向下走一步** $(x, y) \to (x, y+1)$：代表**新增** $B[y]$，編輯距離 $D$ 加 1。
* **對角線走一步** $(x, y) \to (x+1, y+1)$：代表 $A[x] = B[y]$（字元相同），**免費移動，編輯距離 $D$ 不變（權重為 0）**。

**演算法核心（貪婪 + 廣度優先搜尋 BFS）：**
1. **定義斜線 $k$：** 定義 $k = x - y$。向右走會使 $k$ 加 1，向下走會使 $k$ 減 1，走對角線（滑行，稱為 Snake）則 $k$ 值不變。
2. **以編輯步數 $D$ 為外層迴圈：** 我們不以座標 $(x,y)$ 推進，而是探索「當編輯次數為 $D = 0, 1, 2...$ 時，在每一條斜線 $k$ 上最遠能走到哪個 $x$ 座標」。
3. **貪婪滑行：** 每次跨出一步（新增或刪除）到達某條斜線 $k$ 後，若發現 $A[x] = B[y]$，就沿著對角線一路免費滑到底，直到字元不同為止。最先觸碰到終點 $(M, N)$ 的路徑，必定是編輯次數 $D$ 最少的最佳解。

### 2. 複雜度分析
令 $D$ 為兩份檔案的最小編輯距離（即新增與刪除的總行數）：
* **時間複雜度：** 最佳與平均情況為 $O((M + N) \times D)$，最差情況（兩檔案完全沒有相同字元，$D = M+N$）為 $O((M+N)^2)$。在實務上，程式碼修改通常只佔檔案的一小部分（即 $D \ll M+N$），因此執行速度接近線性 $O(M+N)$。
* **空間複雜度：** 僅計算編輯距離只需 $O(D)$ 的一維陣列；若需回溯完整路徑，基礎實作需儲存歷史狀態，空間為 $O(D^2)$（Myers 論文中結合分治法的中點搜尋變體，可將空間進一步壓至嚴格線性的 $O(M+N)$）。

## 綜合比較：LCS 動態規劃 v.s. Myers 演算法

| 比較維度 | 動態規劃 (標準 LCS) | 非動態規劃 (Myers 演算法) |
| :--- | :--- | :--- |
| **演算法核心思想** | 狀態轉移填表（Bottom-up 窮舉所有子問題） | 圖論最短路徑搜尋（BFS + 對角線貪婪滑行） |
| **時間複雜度（一般）** | 恆定為 $O(M \times N)$ | $O((M + N) \times D)$，其中 $D$ 為差異大小 |
| **時間複雜度（完全相同）** | $O(M \times N)$（仍須填滿整張表） | **$O(M + N)$**（$D=0$，直接沿對角線滑到底結束） |
| **空間複雜度（含回溯）** | $O(M \times N)$ | $O(D^2)$（搭配分治法可達 $O(M+N)$） |
| **搜尋空間特徵** | 盲目走訪網格中的每一個座標點 $(i, j)$ | **輸出敏感（Output-Sensitive）**：只展開差異點附近的扇形區域 |
| **輸出結果的直覺性** | 取決於回溯時的平手決策（Tie-breaking） | 由於採用貪婪策略，傾向將刪除集中在前、新增集中在後，更符合人類閱讀程式碼區塊的習慣 |

### 為什麼工業界（如 Git）選擇 Myers 而非標準動態規劃？
1. **真實世界的數據特性（$D$ 極小）：** 工程師提交程式碼（Commit）時，往往是在一個 10,000 行的檔案中只修改了 10 行（$M \approx 10000, N \approx 10000, D = 20$）。
   * **標準動態規劃**需要建立並計算 $10000 \times 10000 = 10^8$（一億）個網格，消耗數百 MB 記憶體且明顯卡頓。
   * **Myers 演算法**只針對 $D=20$ 的範圍進行展開，大部分時間都在對角線上高速滑行，運算量僅約 $(10000 + 10000) \times 20 \approx 4 \times 10^5$（四十萬）次操作，差距達 **250 倍以上**。
2. **提早終止（Early Termination）：** 動態規劃必須算完最後一格才知道最終答案；Myers 演算法則是一旦對角線滑行觸碰到右下角終點 $(M, N)$ 就立刻中止搜尋，無須浪費算力在不可能更優的分支上。
